# SparkWright 使用说明书

SparkWright 用于记录灵感、拆解计划、AI 评分与合成、管理开发和内容创作。前端采用 React，服务端采用 Fastify，数据保存在本机 SQLite 数据库中。

本说明适用于本次发布的干净安装包。发布包不含作者的账号、密码、API Key、数据库或备份。截图、二维码、角色名称等界面素材不能作为登录凭据。

个人客户端启动后显示社区登录页，也可选择“先使用本地个人功能”，无需登录即可使用私人工作区。社区账号、聊天、排行榜与管理统计使用独立云端服务；手机仅支持轻量社区功能。新版接入及参榜流程请先阅读 [个人客户端与社区使用指南](个人客户端与社区使用指南.md)。

## 1. 安装与首次打开

### Windows 一键启动

安装 Node.js 22.12+ 并解压项目后，双击项目根目录的 `启动SparkWright.bat`。程序会检查环境，首次运行自动安装依赖，再启动个人版；服务就绪后自动打开浏览器，无需手动输入命令。首次安装需要联网，以后直接双击即可。

请保持启动窗口打开，停止服务时按 Ctrl+C。如果个人版已经运行，再次双击只会打开浏览器，不会重复启动服务。未安装 Node.js、安装失败或端口被其他程序占用时，窗口会保留错误提示供查看。以下手动操作方法仍可使用。

### 环境

- Node.js 22.12 或更新的兼容版本，建议使用仍受维护的 LTS 版本。
- npm、现代浏览器，以及可写的项目目录。
- 安装依赖时需要网络。SQLite 原生模块如无适配的预编译文件，需要系统编译工具。

在解压后的项目根目录打开终端：

```sh
npm ci
npm start
```

Windows 用户先右键 ZIP →「全部解压」，进入能看到 `package.json` 的文件夹。点击资源管理器顶部地址栏，输入 `cmd` 并按回车，然后逐条运行上述命令；等 `npm ci` 安装完成后再运行 `npm start`。

如果打开的是 PowerShell（提示符以 `PS` 开头），请逐条运行以下命令：

```powershell
npm.cmd ci
npm.cmd start
```

出现“无法加载文件 npm.ps1，因为在此系统上禁止运行脚本”时，使用以上 `npm.cmd` 命令即可；不需要管理员权限或修改 PowerShell 执行策略。等待安装完成后再启动，以后在 PowerShell 中启动只需 `npm.cmd start`。

保持命令窗口打开，在浏览器地址栏输入 `http://127.0.0.1:5318`，登录社区或点击“先使用本地个人功能”。停止服务时，在启动终端按 Ctrl+C。以后启动只需运行 `npm start`。本地工作区不需要运行 `npm run account:init`；它不能初始化云端 owner。

开发时运行 `npm run dev`，访问 `http://127.0.0.1:5310`。开发界面把 `/api` 请求转发到本地服务端。端口可在自己的 `.env` 中通过 `PORT`、`WEB_PORT` 修改。

首次运行会自动创建 `data/ideabox.db`。`.env` 与 `data/` 是个人运行数据，请保管并备份，不要上传、分享或覆盖。

升级已有的单账号个人版时，原用户 ID、灵感与 AI 配置会沿用；无需旧密码。若数据库中有多个账号，程序会拒绝自动选择，保留原数据由维护者处理。不要删库或合并账号来绕过此提示。

私人工作区只供本机访问：服务监听 `127.0.0.1`，并检查 Host、客户端地址和请求来源；不要公开它。多人聊天和公开榜单通过独立的社区部署包提供，不再部署完整私人工作台。

### 多人版账号与角色

新社区由作者在服务器终端独立初始化 owner 后开放注册。社区注册填写昵称、邮箱和密码，不发送验证码，不依赖 SMTP；首个公网注册者始终是普通用户。本地身份不能转换成云端 owner。

| 角色 | 使用权限 |
| --- | --- |
| user | 自己的灵感、计划、AI 配置、创作资料；允许范围内的公开广场、频道和排行榜；提交、查看自己的反馈 |
| admin | 普通用户功能及后台授权的分析、反馈、公告等管理能力 |
| owner | 最高管理角色，负责角色管理、广场治理、公共频道等 owner 专属操作 |

以后台实际显示和服务端权限校验为准。管理员权限不等于可以随意获取其他用户的私人内容或 API Key。发布包不带作者原来的管理员账号。

## 2. 配置 AI

进入「设置」，填写自己服务商提供的 Base URL、API Key 和模型名称。Base URL 应为 OpenAI 兼容接口的根地址，代码会追加 `/chat/completions`；不要重复填写该后缀。按提供商说明填写实际模型标识，保存后使用页面的测试入口检查配置。

「获取 API Key」打开整理好的平台资源页。外部平台的密钥、额度、计费与模型能力由该平台管理。AI 操作会向你配置的平台发送当前任务所需的灵感或上下文，请自行决定是否提交敏感内容。

本地个人配置优先于本机可选共享配置。社区需要在“我的社区投稿”单独填写自己的 Key，社区部署禁止默认启用作者付费 Key；不能通过本地配置自动同步。

目前个人 Key 存储在服务端 SQLite 中，数据库文件与备份需要按凭据保管。不要将 Key 写进 `VITE_` 环境变量、前端源码、Issue 或截图。未配置可用模型时，记录和管理功能仍可使用，AI 操作会提示缺少配置。

## 3. 我的灵感与计划

进入「我的灵感」，新建标题、正文、标签、截止日期与状态。可搜索、筛选，并按更新时间、创建时间、截止、分数或进度排序。

在详情中编辑灵感、维护计划步骤、记录创作进度，并使用 AI 辅助拆解。修改标题或正文后，已有评分记录仍可追溯，但旧内容的评分不能代表新的正文。仅更改标签等管理信息不会改变评分输入版本。

私人灵感默认只对自己的账号可见。发布到广场或报名排行榜前，请检查公开说明与正文，确认没有私人联系方式、密钥或未授权内容。

## 4. AI 评分与排行榜

点击灵感详情里的「开始评分」。当前使用 V5 标准角度：四个维度、十二个子项，由模型给出等级和证据，服务端按固定规则计算分数，以一位小数显示。旧评分保留为历史记录，不会重新启动已废弃的评分引擎。

评分需要等待模型返回。模型输出不完整、格式不合规或服务异常时，页面会显示错误；请检查 AI 配置与服务商额度后重试。AI 分数仅作为创作参考，不保证商业收益。

「评分历史」保留本机各次记录。公共排行榜需选择单条正文上传为社区草稿，在云端可信评分后主动公开并参榜；默认不参与。不能直接上传本地分数或耗时成为可信榜单结果。排行榜沿用 V5 精度与同分规则，排除原评分超过60秒和100.0分。60秒为资格限制，不是模型终止时间。

## 5. 灵感合成

进入「灵感合成」，选择两条不同的、你有访问权限的灵感 A 与 B。系统可结合双方的优点、缺点和机制，以随机变化生成候选，再对结果进行评分。

合成不要求比原始灵感提高 3.0 分，也不保证结果更好；结果分数可以升高或降低。生成后检查标题、正文、来源与评估信息，需要保留时点击「导入我的灵感」，再进行二次创作。

同一次请求进行中不要连续点击开始。可使用界面提供的取消入口，取消后再重新操作。输入同一条灵感两次、访问无权限来源或模型服务失败时不能完成合成。

## 6. 广场与频道

「灵感广场」连接同一公共社区。公共频道实时推送消息，在线人数按有效连接中的社区账号去重，是近实时值；同账号多个标签页只计一人。

owner 可按后台权限下架或恢复公开灵感、禁言或解除禁言、维护公共频道。下架公开内容不等于删除作者的私人灵感。被禁言用户的个人记录功能与广场发言权限分别处理。

本地私人内容不会自动上传；社区里明确公开的投稿和榜单在电脑与手机间共享。旧本地公开标记不会自动成为社区投稿。

## 8. 灵感酱、主题与语言

电脑登录页先显示首帧与可操作表单，条件合适时延后启动循环动效；手机只挂载静态图，不创建播放器。电脑灵感酱保留粒子角色、岛屿与交互，并提供低画质、失败重试和静态占位。手机社区不加载此场景。

在「设置」或社区页面切换中文 / English，以及星空、玻璃、Notion、粗野四种主题。手机使用独立的轻量社区构建入口。系统的减少动态效果偏好会影响动效展示。

## 9. 反馈与通知

「用户反馈」可提交 Bug、建议和问题，并查看自己的反馈状态与回复。描述中写明操作步骤、预期结果、实际结果、浏览器和出现时间；不要提交密码、API Key、验证码或别人的私人数据。

管理后台的反馈收件箱支持查看、筛选、状态处理、回复和内部备注。内部备注不向提交者公开；面向用户的回复通过系统反馈与通知展示。关闭反馈用于表示处理结束，不会撤销已经发生的操作。

社区反馈发送到社区管理员收件箱，用户可在反馈页面查看状态和回复。没有社区连接时可通过 GitHub Issues 反馈源码问题；本地私人通知不自动同步。

社区后台分开显示聊天活跃与社区活跃的过去24小时、7天、30天去重人数及趋势。管理账号、登录、自动轮询和心跳不计入；不观察用户的本地私人活动。统计不等于网页访问量或精确在线人数。

## 10. 数据导出、备份与升级

在设置里使用个人数据导出，备份自己的资料。管理员备份功能与个人导出不同，服务器备份可能包含全站用户数据与 Key，只有授权维护者应处理。

更新前停止服务并备份自己的 `.env` 与 `data/`，再替换源码和安装对应锁文件的依赖。保留原运行数据；应用通过守卫式迁移升级 SQLite。不要把新发布包的空数据目录覆盖旧数据库，也不要复制其他人的数据库来登录。

需要回退时，使用对应版本源码、锁文件及升级前的一致数据库备份。旧版本未必能够读取升级后的数据库，不能只替换 JS 文件就声称完成回滚。
